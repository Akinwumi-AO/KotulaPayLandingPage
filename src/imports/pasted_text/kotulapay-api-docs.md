H2H Payments Section

Overview

Explain Host-to-Host payments and describe the flow:

Merchant initiates payment

Customer completes payment

KotulaPay validates transaction

Webhook notification is sent

Merchant verifies payment

Flow Diagram

Payment Flow

Merchant System

Creates the payment request and starts the checkout flow.

KotulaPay API

Receives the request, validates it, and prepares the transaction.

Payment Processing

The transaction is processed through KotulaPay’s payment infrastructure.

Customer Payment

The customer completes the payment using the generated payment link or checkout page.

Webhook Notification

KotulaPay sends a signed webhook event with the updated transaction status.

Merchant Confirmation

The merchant verifies the payment and updates the order or service state.

Create H2H Payment
POST

/payments/h2h/create

Creates a new host-to-host payment transaction and returns a payment link and transaction reference.

Payment Status Verification
GET

/payments/verify/{reference}

Verifies the current status of a transaction using the merchant reference.

"currency": "NGN",

}
}

Webhook Events

Supported Events

payment.pending — Payment has been created and is awaiting customer action.

payment.processing — Payment is being processed.

payment.success — Payment completed successfully.

payment.failed — Payment failed or was canceled.

Example Webhook Payload

payment.success webhook

{
"event": "payment.success",
"data": {
"reference": "INV-2026-0001",
"amount": 5000,
"currency": "NGN",
"payment_status": "success",
"paid_at": "2026-01-15T10:20:00Z"
}
}

Verify webhook signatures before processing events to ensure the payload originated from KotulaPay.
